# Inky round 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The onboarding works everywhere. The app has much more motion. Every service shows its real logo. All connectors work from the desktop app. Any computer is easy to connect. Posted agents are available to everyone through a GitHub library.

**Architecture:**
- **UI modules:** the web UI gets `motion.js` and a `logos/` folder; `life.js` gets idle behaviours.
- **Engine modules:** `connectors.py` (built-in Telegram, n8n and Apify providers plus Claude Code/Codex status), `connect.py` (install, SSH, LAN beacon, Tailscale) and `library.py` (checker, index, install, domain guard).
- **Desktop app:** gains `inky://` deep links.

**Tech Stack:** Python 3.12 stdlib + Playwright + httpx; vanilla JS; Tauri 2 + `tauri-plugin-deep-link`; POSIX `sh` for `install.sh`; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-30-inky-round3-design.md`

## Global Constraints

- No new runtime Python packages. At most one new Tauri crate (`tauri-plugin-deep-link`).
- The UI stays v2; critters are the only illustrations; no stock or AI imagery.
- Logos: official, unmodified, sourced in `inky/ui/logos/SOURCES.md`.
- SSH: `BatchMode=yes` only (keys, never passwords). Never broadcast a pairing code or token.
- Library agents never carry cookies, memory, results or chat. Replay keeps them on their listed domains.
- Tests: `.venv/bin/python -m unittest discover -s tests -t .`, `node --test inky/ui/*.test.mjs`, `cargo test` in `desktop/src-tauri`.
- After any `inky/` change: `python desktop/scripts/build-engine.py` before building the app.

## Part 2 · Motion

### Task 3: App motion
**Files:** Create `inky/ui/motion.js`; modify `inky/ui/index.html`, `inky/ui/app.css`, `inky/ui/app.js` (route calls `MOTION.enter(el)`), `inky/ui/views.js` (counters)

**Interfaces:**
- `MOTION.enter(root)` staggers children marked `[data-enter]` or the default selectors (`.card, .botcard, .desk, .m, .rule, .stat`).
- `MOTION.count(el, to)`.
- `MOTION.press()` is installed once.
- `MOTION.calm()` means reduced motion.

- [ ] Step 1: `motion.js`, using the Web Animations API:
  - `enter` uses `el.animate([{opacity:0,transform:'translateY(8px)'},{opacity:1,transform:'none'}],{duration:320,delay:i*30,easing:'cubic-bezier(.2,.8,.2,1)',fill:'backwards'})`, limited to the first 24 children;
  - `count` animates the number with requestAnimationFrame over 600 ms;
  - press is a pointerdown/up scale on `.btn,.iconbtn,.botcard,.desk,.chip` via CSS `:active{transform:scale(.97)}`, with a spring-back `transition:transform .18s cubic-bezier(.3,1.6,.5,1)`.
- [ ] Step 2: CSS:
  - card hover lift `transform:translateY(-2px);box-shadow`;
  - toast spring keyframes;
  - `.pill.live i` pulse;
  - progress bar `transition:width .5s`;
  - `::view-transition` slide.
  - All of it off under reduced motion.
- [ ] Step 3: Wire it: `route()` calls `MOTION.enter($("#view"))` after `show`; `refresh()`-driven re-renders don't re-enter (only on route). Diary and Activity stats use `MOTION.count`.
- [ ] Step 4: Check by eye (screenshots) and commit: "Motion: springy entrances, press feedback, counters, live pulse".

### Task 4: Critter life v2
**Files:** Modify `inky/ui/critter.js` (per-limb groups), `inky/ui/life.js` (behaviour scheduler, reactions), `inky/ui/app.css`, `inky/ui/life.test.mjs`

**Interfaces:**
- `nextBehaviour(seed, n, mood)` returns `{name: "look"|"sway"|"yawn"|"stretch"|"blink2"|"none", at: ms}`, deterministic.
- `LIFE.react(svg, kind)` for `hover|click|results|needs|learned`.

- [ ] Step 1: Write the tests.
  - `nextBehaviour` is deterministic for a seed.
  - Two seeds never share the same first 5 beats.
  - Asleep only gives "none" or "sway".
  - Working gives no yawns.
  - Delays fall in 2.5–9 s.
- [ ] Step 2: Implement.
  - `critter.js` wraps each tentacle `<path>` in `<g class="limb" style="--i:N">`, the cat paws likewise, and the blob's bottom edge in `.limb`. It adds a `.mouth` class to the mouth path and a hidden `.yawn` ellipse.
  - CSS: `.limb{transform-origin:… ;animation:c-sway 3.2s ease-in-out infinite;animation-delay:calc(var(--i)*-.4s)}`. Behaviour classes `.b-look` (pupils translate ±3), `.b-yawn` (.yawn shown, eyes .4), `.b-stretch` (scaleY 1.08 → 1).
  - The single scheduler loop sets the class for the behaviour's length.
  - Reactions: hover (pointerenter on `svg.critter` larger than 30 px) → `.r-wiggle` for 600 ms; click → `.r-squish`; the SSE `results` event → `.r-dance` on that bot's critters; `needs` → a `.r-jump` every 8 s while waving.
- [ ] Step 3: Run the tests. Gallery screenshot check. Commit: "Critters: tentacles sway, they look around, yawn, stretch and react to you".

- [ ] Step 1: Tests.

- [ ] Step 3: Routes:
