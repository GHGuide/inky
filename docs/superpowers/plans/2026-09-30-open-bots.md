# Inky open bots · implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the local-first Inky bots app from the spec, connect it to Claude Code and Codex over MCP, and test every feature end to end.

**Architecture:** A Python engine (`inky/`, stdlib + Playwright) serves a JSON API, SSE and MJPEG, plus a vanilla-JS UI in the v2 look.
Each bot owns one thread and one Playwright browser. Skills are recorded steps that replay with no model.

**Tech Stack:** Python 3.12, sqlite3, http.server, Playwright 1.63 (installed), vanilla JS/CSS, MCP over stdio JSON-RPC.

**Spec:** `docs/superpowers/specs/2026-09-30-open-bots-design.md`

## Global Constraints

- No new Python dependencies: use the stdlib and the already-installed Playwright.
- Never print keys, and never put keys on a command line. The keychain is written through `security -i` stdin.
- Never contact anyone. Tests use local fixture sites; the only real sends go to local fake endpoints.
- Irreversible steps always wait for approval. No step may type into a password field or solve a robot check.
- Work stays on branch `build`. Commit after each task.
- Data lives in `INKY_HOME` (default `~/.inky`). Tests use a temporary home.
